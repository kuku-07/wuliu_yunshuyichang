> 版本 v0.1 · 2026-10-30 · **只给接口设计，确认后再写代码**
> 复用阶段 1：[phase1_cli.py](../prototype/phase1_cli.py) 的检索、闸门、护栏、LLM 抽象
> 关联：[架构选型方案](03-架构选型方案.md) 第 3 节表结构

## 0. 与原题（报销助手）的六处关键差异

| 原题设计 | 本项目调整 | 原因 |
| --- | --- | --- |
| `POST /chat` 只收 `{session_id, question}` | 增加 `shipment_no` / `lane_scope`（可选），并在**流开始前**做运单级授权预检 | 客户只能查自己授权的运单（f40）；等生成完再拦就晚了 |
| 历史 6 轮直接拼进上下文 | 6 轮 = 6 组问答，且**历史只存脱敏后的内容**，不回放受限字段 | 定位、电话属受限数据；历史回放等于二次泄露 |
| 引用显示「文件名 + 片段」 | 引用必须带 **文档版本 + 生效日期 + 适用线路 + 章节 + 片段** | 规则有版本，争议要记录使用版本（f24） |
| 红线问题返回错误码 | 红线是**正常业务结果**：HTTP 200 + `takeover` 事件 | 错误码会被前端当成「系统坏了」；接管是一种正确行为 |
| 回答直接展示给用户 | 回答固定标注「仅内部参考，不对外发送」 | 本系统只出草稿，客服主管签核后才可对外（f22、f15） |
| 只存会话与消息 | 额外存 `citations` 与审计事件，能重建一次回答 | 审核日志要能重建当次处理（f45） |

**一句话原则：错误码只描述技术/权限失败；业务状态（接管、需复核）走事件，不伪装成报错。**

## 1. 接口总览

| 方法 | 路径 | 用途 | 是否流式 |
| --- | --- | --- | --- |
| POST | `/api/v1/sessions` | 新建会话，返回 session_id | 否 |
| GET | `/api/v1/sessions/{session_id}/messages` | 加载最近 6 轮历史 | 否 |
| POST | `/api/v1/chat` | 提问，SSE 流式回答 | 是 |
| GET | `/api/v1/health` | 探活（不查库、不调模型） | 否 |

统一要求：

- 鉴权：`Authorization: Bearer <token>`；开发环境可用 `X-Debug-User: <employee_no>`，**生产禁用**。
- 所有非流式响应统一包络：
  ```json
  {"code": "OK", "message": "", "data": {}, "request_id": "r_xxx"}
  ```
- 所有错误先给 **HTTP 状态码 + 业务错误码 + 中文 message**，不返回裸字符串或英文异常。
- `request_id` 全链路透传，前端展示在错误气泡里，便于查日志。

## 2. POST /api/v1/chat

### 2.1 请求

```json
{
  "session_id": "s_01J...",
  "question": "客户临时改地址，异常该怎么分类？",
  "client_msg_id": "c_01J...",
  "shipment_no": "YD20261030001",
  "lane_scope": "试点干线-华东"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| session_id | 是 | 会话 ID，必须属于当前用户 |
| question | 是 | 1–2000 字符；超过 2000 返回 `QUESTION_TOO_LONG` |
| client_msg_id | 否 | 幂等键，网络重试时复用；同一会话内唯一 |
| shipment_no | 否 | 指定运单时触发 ABAC 预检 |
| lane_scope | 否 | 缺省取会话绑定线路，避免跨线路口径混用（f50） |

### 2.2 响应头（流式）

```http
HTTP/1.1 200 OK
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache, no-transform
Connection: keep-alive
X-Accel-Buffering: no
```

- 每 15 秒发送一行注释心跳 `: ping`，防止网关断连。
- 禁止开启响应压缩，否则 SSE 会被缓冲，前端看不到逐字输出。

### 2.3 SSE 事件协议

按发生顺序：

| event | data（JSON） | 触发时机 |
| --- | --- | --- |
| `meta` | `{request_id, session_id, user_message_id}` | 连接建立后立即 |
| `status` | `{stage: "retrieving"\|"generating"\|"verifying", label: "正在检索规则…"}` | 阶段切换 |
| `delta` | `{text: "……"}` | 模型逐段输出 |
| `citations` | `{items: [Citation]}` | 生成结束前一次性发送 |
| `takeover` | `{reason_code, message, matched_terms}` | 红线命中（**不调用模型**） |
| `guardrail` | `{passed, needs_review, violations}` | 输出自检后 |
| `done` | `{assistant_message_id, latency_ms, prompt_version, model, data_time}` | 正常结束 |
| `error` | `{code, message, retryable}` | 流内异常 |

`Citation` 结构：

```json
{
  "doc_id": "doc_001",
  "doc_title": "运输异常处置与签收协作规则（试点版）",
  "version": "0.1",
  "effective_from": "2026-11-01",
  "lane_scope": "试点干线-华东",
  "section": "2. 异常分类",
  "chunk_id": 3,
  "quote": "客户临时改地址、卸货排队和封路属于不同处理路径……",
  "score": 0.87
}
```

三条流式样例：

```text
event: meta
data: {"request_id":"r_01J","session_id":"s_01J","user_message_id":"m_01J"}

event: status
data: {"stage":"retrieving","label":"正在检索规则…"}

event: delta
data: {"text":"异常分为固定核心类型，"}

event: citations
data: {"items":[{"doc_title":"运输异常处置与签收协作规则（试点版）","version":"0.1","section":"2. 异常分类","quote":"……","score":0.87}]}

event: guardrail
data: {"passed":true,"needs_review":false,"violations":[]}

event: done
data: {"assistant_message_id":"m_02J","latency_ms":4200,"prompt_version":"phase2.v1","model":"gpt-4o-mini","data_time":"2026-10-30T09:12:00+08:00"}
```

红线命中时**不出现任何 `delta`**：

```text
event: meta
event: status {"stage":"gated","label":"正在判断接管条件…"}
event: takeover {"reason_code":"REDLINE_COMPENSATION","message":"涉及赔付或赔偿认定，规则要求人工接管，系统不生成任何金额建议。","matched_terms":["赔多少"]}
event: guardrail {"passed":true,"needs_review":false,"violations":[]}
event: done
```

### 2.4 错误码表

流开始前的错误用 HTTP 状态码 + JSON；流开始后的异常用 `event: error`。

| 错误码 | HTTP | 中文 message | 何时 |
| --- | --- | --- | --- |
| `INVALID_REQUEST` | 400 | 请求参数不合法：{字段原因} | 缺字段、类型错误 |
| `QUESTION_TOO_LONG` | 422 | 问题超过 2000 字，请精简后重试 | 超长 |
| `UNAUTHENTICATED` | 401 | 未登录或登录已过期，请重新登录 | 无 token 或 token 过期 |
| `SESSION_FORBIDDEN` | 403 | 无权访问该会话 | 会话不属于当前用户 |
| `SHIPMENT_FORBIDDEN` | 403 | 你无权查询该运单，请联系管理员授权 | ABAC 预检失败 |
| `SESSION_NOT_FOUND` | 404 | 会话不存在或已关闭 | 会话不存在 |
| `SESSION_BUSY` | 409 | 当前会话正在回答，请等待完成 | 同一会话并发请求 |
| `RATE_LIMITED` | 429 | 提问过于频繁，请稍后再试 | 超过 10 次/分钟 |
| `LLM_UPSTREAM_ERROR` | 502 | 模型服务异常，本次未生成回答 | 上游 5xx |
| `LLM_TIMEOUT` | 504 | 模型响应超时，请稍后重试 | 超时 |
| `KNOWLEDGE_UNAVAILABLE` | 503 | 规则库暂不可用，请稍后重试 | 检索索引不可用 |
| `INTERNAL_ERROR` | 500 | 系统内部错误，请联系管理员（编号 {request_id}） | 兜底 |

流内错误示例：

```text
event: error
data: {"code":"LLM_TIMEOUT","message":"模型响应超时，请稍后重试","retryable":true}
```

**注意**：红线不产生错误码。禁止把「需人工接管」「需复核」写成 4xx/5xx。

### 2.5 状态与幂等

- 同一 `session_id` 同时只允许一个流；重复进入返回 `SESSION_BUSY`。
- 同一 `client_msg_id` 重复提交：若已完成，直接回放已存结果；若正在流式，返回 `SESSION_BUSY`。
- 客户端断开：服务端停止生成，消息标记 `aborted`，**不写入完整回答**；已产生的片段不入历史上下文。
- 历史窗口：最近 **6 组问答**（12 条消息），超过则丢最旧；总 token 上限 1500，超限继续从最旧丢。
- 历史中的助手消息只保留「答案 + 引用标题 + 是否接管」，不保留完整检索片段，避免上下文膨胀。

## 3. 数据存储（SQLite，沿用阶段 1 表结构）

### 3.1 表

| 表 | 关键字段 | 约束 |
| --- | --- | --- |
| `users` | id, employee_no, name, persona, org_id, status | unique(employee_no) |
| `sessions` | id, user_id, lane_scope, shipment_no, status, created_at, last_active_at | index(user_id, last_active_at) |
| `messages` | id, session_id, client_msg_id, role, content, status, intent, prompt_version, model, data_time, confidence, latency_ms, created_at | unique(session_id, client_msg_id)；index(session_id, created_at) |
| `citations` | id, message_id, doc_id, doc_title, doc_version, effective_from, lane_scope, section, chunk_id, quote, score | index(message_id) |
| `audit_logs` | id, actor_id, action, object_type, object_id, rule_version, request_id, created_at | **只追加，禁止 update/delete** |

`messages.status` 枚举：`pending` / `streaming` / `complete` / `takeover` / `aborted` / `error`。
`messages.role` 枚举：`user` / `assistant`。

### 3.2 写入顺序（保证中途失败也能审计）

1. 收到请求 → 插入 user 消息（`status=complete`），记 `request_id`。
2. 闸门命中 → 插入 assistant 消息（`status=takeover`），写审计，结束。
3. 正常生成 → 先插入 assistant 消息（`status=streaming`），流结束后更新为 `complete` 并写 `citations`。
4. 客户端断开 / 上游失败 → 更新为 `aborted` 或 `error`，**不补全内容**。
5. 每次状态变更都追加一条 `audit_logs`，不覆盖历史。

## 4. 前端单页聊天界面

### 4.1 结构

```text
┌────────────────────────────────────────────┐
│ 顶部：线路选择（只读）· 会话状态 · 新建会话   │
├────────────────────────────────────────────┤
│ 消息区（可滚动）                            │
│  ┌ 用户气泡 ────────────────────────────┐  │
│  └──────────────────────────────────────┘  │
│  ┌ 助手气泡 ────────────────────────────┐  │
│  │ 正文（打字机逐字出现）                │  │
│  │ [需人工接管] 横幅（如有）             │  │
│  │ [需人工复核] 横幅（如有）             │  │
│  │ ▸ 引用来源（3）  文档 · 版本 · 章节    │  │
│  │ 仅内部参考，不对外发送                │  │
│  └──────────────────────────────────────┘  │
├────────────────────────────────────────────┤
│ 输入框（多行）· 发送按钮 · 字数 0/2000       │
└────────────────────────────────────────────┘
```

### 4.2 状态机

| 状态 | 触发 | 界面表现 |
| --- | --- | --- |
| `idle` | 初始 | 输入可用 |
| `submitting` | 点击发送 | 禁用发送，插入用户气泡 |
| `retrieving` | 收到 `status.retrieving` | 助手气泡显示「正在检索规则…」+ 骨架 |
| `generating` | 首个 `delta` | 打字机逐字追加，隐藏骨架 |
| `verifying` | 收到 `status.verifying` | 气泡底部显示「正在校验引用…」 |
| `done` | 收到 `done` | 显示引用面板、耗时、数据截至时间 |
| `takeover` | 收到 `takeover` | 橙色横幅 + 原因码 + 「复制交接信息」；不显示引用 |
| `needs_review` | `guardrail.needs_review=true` | 黄色横幅「此回答需人工复核」 |
| `error` | 收到 `error` 或 HTTP 错误 | 红色气泡 + 中文原因 + 重试按钮 + request_id |
| `retrieving` 超时 | 8 秒无首个事件 | 提示「检索较慢，仍在处理…」 |

### 4.3 打字机实现要点

- 用 `requestAnimationFrame` 按帧消费缓冲区，每帧 2–4 个字符，不用 `setTimeout` 逐字（会掉帧）。
- 缓冲区积压超过 200 字符时一次性追平，避免「回答完了还在慢慢打字」。
- 只对 `delta` 文本做渲染，不做 Markdown 全量重解析（每帧重解析会卡）。
- 流结束若仍有缓冲，加速到每帧 12 字符收尾。

### 4.4 引用面板

- 折叠态显示「引用来源（3）」；展开后每条：
  - 文档标题 + `v版本` + 生效日期 + 章节
  - 片段原文（最多 80 字，超出折叠）
  - 检索分（仅调试模式显示，生产隐藏）
- 点击引用条目不跳外链，只做展开/收起（阶段 2 无原文详情页）。
- 引用为空时显示「未命中规则文档，需人工确认」，而不是留空。

### 4.5 必须显示的固定文案

- 输入框上方：`回答仅供内部参考，不对外发送`
- 接管横幅：`已转人工接管，系统不提供自动建议`
- 复核横幅：`该回答未通过自动校验，请人工核对后再使用`

## 5. 安全与审计

| 项 | 设计 |
| --- | --- |
| 鉴权 | Bearer Token / 企业 SSO；会话归属校验，越权返回 403 |
| 运单授权 | 请求带 `shipment_no` 时，流开始前查 `authorization_grants`；未授权不检索 |
| 字段最小化 | 问题与答案入库前脱敏手机号、车牌、地址；原文不落 `messages` |
| 提示注入 | 用户输入只作为数据；检索结果与系统提示分离；不允许聊天中触发工具执行 |
| 限流 | 每用户 10 次/分钟、每会话 1 个并发流 |
| 审计 | 记录 question、answer、citations、gate 结果、prompt_version、model、request_id |
| 留存 | 90 天；到期由安全与合规主管确认删除或归档 |

## 6. 验收口径（阶段 2）

| # | 项 | 标准 |
| --- | --- | --- |
| 1 | 首字延迟 | 本地检索 ≤2 秒；API 模式 ≤5 秒 |
| 2 | 引用完整率 | 100% 非接管回答至少 1 条引用，且带版本与生效日期 |
| 3 | 红线 | 0 次模型调用，0 条 `delta`，必出 `takeover` |
| 4 | 历史窗口 | 最多 6 组问答；超限丢最旧且不报错 |
| 5 | 中断 | 客户端断开后消息为 `aborted`，不进入历史 |
| 6 | 错误文案 | 全部中文，含 `request_id`，无堆栈泄露 |
| 7 | 越权 | 未授权运单在流开始前被拒，且不产生模型调用 |

## 8. 需要你确认的 5 个点

1. **会话是否绑定运单**：绑定后授权更严，但一个会话只能聊一票；不绑定则每次请求都要带运单号。
2. **6 轮是否够**：客服一次排查可能超过 6 轮，是否改为「6 轮 + 旧内容摘要」。
3. **红线命中后是否允许继续追问**：当前设计允许新问题，但不允许对同一接管话题追问细节。
4. **前端是否给承运商使用**：若开放，需增加承运商主体级授权与独立话术。
5. **是否需要在流里返回置信度**：当前只在 `done` 里给 `data_time`，未给逐条置信度。

确认后我再写 FastAPI + SQLite + 单页前端的完整代码。
