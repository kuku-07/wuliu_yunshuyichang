# 需求评审十问 · 运输异常与签收协作智能体系统

> 角色：需求评审专家 / 架构师
> 输入：`discovery-report.md`（远川物流，访谈证据 f00–f55）
> 状态：**全部答案都是待验证假设**。标注「已采集」= 有访谈陈述支撑；「待确认」= 证据缺口，需访谈或试点补采。

## Q1 这一期到底做到哪一步：只做「答复辅助」，还是做「异常闭环」？

**为什么先问**
它决定系统是「一个问答工具」还是「一条带状态、带待办、带责任人的工作流」。两者在状态机、权限、并发和验收上完全不同。

| 答案分支 | 架构差异 |
| --- | --- |
| 只做查单问答 | 无状态或轻会话，检索 + 生成即可；不需要待办、升级、接管状态机 |
| 做异常闭环 | 必须有事件状态机（已报→已受理→处理中→超时升级→已闭环）、具名责任人、截止时间、退回原因、转交留痕 |
| 做判责/结算 | 增加计算引擎、争议流程、对外法律口径；风险等级最高 |

**本项目答案（假设）**
做「异常闭环的辅助」但不做判责结算：异常必须落到**处理人 + 截止时间 + 退回原因**，超时交运输负责人协调 [f25]；交接要带齐轨迹、计划、运单映射、异常记录与回执、当前版本与未解决事项，**接手人明确确认后才结束本岗待办**，「发消息不等于责任转移」[f23]。不自动结算、不自动扣罚承运商 [f52]。
**状态**：已采集（业务规则清晰）；判责边界已明确排除。

## Q2 异常类型怎么定义：固定枚举，还是可配置分类树？

**为什么先问**
异常分类是整套系统的「主键」。分类不稳定，事件归一、路由、误报统计全部失真；分类过度自由，规则没法写、指标没法算。

| 答案分支 | 架构差异 |
| --- | --- |
| 固定 8–12 类枚举 | 事件 schema 可硬编码，规则可读、开发快；新增类型要发版 |
| 可配置分类树 + 原因码 | 需要元数据驱动的事件模型、配置后台、规则版本管理；灵活性换复杂度 |
| 让大模型自由抽取分类 | 需要标注集与评测集、置信度阈值、人工复核队列；误报不可控，不适合作为责任依据 |

**本项目答案（假设）**
「**固定核心枚举 + 可配置原因码**」：核心类型先收窄（延误/改地址/卸货排队/封路/GPS 异常/货损/回执缺失等），原因码可运营配置。司机侧「先选类型、再补关键信息」，**不允许大模型直接定级**，模型只做候选抽取，定级由规则或人确认。
**理由**：现场最痛的不是司机不报，而是「报的时候说不清是哪一类」，一线要回头补问 [f11]；GPS 不更新可能是隧道弱网也可能是停驶，不能一律判延误 [f10]；关键原因目前没有作为结构化字段随业务交接 [f14]。
**状态**：已采集痛点；枚举清单待与运输负责人确认。

## Q3 运单号和承运商子单号是什么关系？节点时间以谁为准？

**为什么先问**
这是本项目的「数据地基」。多对多映射 + 多来源时间 + 版本并存，直接决定预警可信度和误报率能否 ≤10%。

| 答案分支 | 架构差异 |
| --- | --- |
| 一对一 | 直接 join，单主键，简单 |
| 多对多（实际） | 需独立**映射服务**：主编号、事件时间、来源、版本四要素校验；节点时间归并策略（来源优先级/最早/最晚）；去重键要定（运单号还是子单号） |
| 多来源冲突不处理 | 同一运单出现两个节点时间，预警与回复自相矛盾，误报率无法统计 |

**本项目答案（假设）**
以 **TMS 运单号为主键、承运商子单为从属**，建带版本的映射表；每个节点必须校验**主编号、事件时间、来源、版本**，缺关键字段进**人工修复队列，不用猜测值补齐** [f33]。同一运单多子单的节点时间**按来源优先级 + 事件时间归并**（具体规则待 TMS 工程师出样例）。接口失败恢复后**按业务编号去重补齐**，不重复创建待办 [f35]。
**待确认**：去重键用运单号还是子单号；归并时快照时间与补齐事件时间冲突以谁为准。

## Q4 集成做到多深：只读查询，还是要回写 TMS / 接微信群？

**为什么先问**
读和写的架构成本差一个量级。写回需要幂等、补偿、冲突处理、写权限与 SLA；接 IM 需要消息归一、脱敏与非结构化抽取。

| 答案分支 | 架构差异 |
| --- | --- |
| 只读（查单 + 异常记录） | 适配器 + 快照缓存 + 时效标记 + 降级开关；无事务一致性要求，风险低 |
| 回写状态 / 自动派单 | 双向集成、幂等键、补偿任务、冲突解决、写权限审批、接口 SLA |
| 接入 IM 群消息 | IM 网关、消息归一、说话人识别、非结构化抽取、隐私过滤；噪声与合规成本高 |

**本项目答案（假设）**
**只读**。现有能力边界：TMS 只有查单与异常记录接口，**没有给车辆下发路线控制的能力** [f32]；GPS 每 5 分钟更新 [f30]。首期所有动作只在助手侧形成待办与草稿，**不回写 TMS**。IM 群消息**不作为自动数据源**（可作为人工留痕补充，待确认）。
**状态**：接口能力已采集；IM 范围待确认。

## Q5 回复是「草稿」还是「直接对客户发」？谁审核？

**为什么先问**
这一个选择决定责任归属、合规路径和产品形态。直接对外需要发送网关、模板治理、频控、撤回；草稿需要审核工作台与采纳率指标。

| 答案分支 | 架构差异 |
| --- | --- |
| 内部草稿 | 审核工作台 + 修改留痕 + 采纳率/修正率指标；无发送通道，风险最低 |
| 直接对外发送 | 发送网关、模板白名单、频控与撤回、话术审批、责任重新界定 |
| 自动对承运商派单 | 需要承运商侧入口与回执确认，协作与投诉风险上升 |

**本项目答案（假设）**
**内部草稿制**：先给客服/调度看，**客服主管核对后才可对外**；涉及 GPS 弱网、客户改地址、回执延迟的，必须先由客服主管核对，**未经确认的结果不能覆盖原记录** [f15]。回复必须显示原记录与数据更新时间、置信度 [f31]；**模型不得直接承诺赔付金额**，承诺需主管批准 [f22]。
**状态**：已采集，属于硬约束。

## Q6 升级路由按什么触发：超时、异常类型，还是混合？

**为什么先问**
路由规则决定「15 分钟」是真降本还是把问题更快甩出去。纯硬编码改不动，纯自动又压不住红线。

| 答案分支 | 架构差异 |
| --- | --- |
| 纯超时升级 | 定时器 + 待办队列，简单；但不区分风险等级 |
| 纯类型分级 | 分类→路由表，简单；但慢异常可能永远不升级 |
| 混合 + 可配置版本化 | 规则引擎 + 配置后台 + 生效日期 + 适用范围 + 回放测试；红线单独硬编码 |

**本项目答案（假设）**
**混合**：红线（赔付/危险品/紧急事故）**硬编码拦截、不可配置** [f41]；业务路由（类型分级 + 超时升级）**可配置且版本化**——规则由业务负责人维护，保存生效日期与适用范围，争议要记录使用版本并由合规确认 [f24]。分派必须写明处理人、截止时间、退回原因，超时交运输负责人 [f25]。
**待确认**：15 分钟与误报 10% 的分母、统计周期、排除规则由谁固定、何时定 [f53]。

## Q7 人工接管之后，机器人退不退出？修改能不能覆盖原记录？

**为什么先问**
接管语义决定审计能否重建过程，也决定权限模型是否需要「建议通道」与「执行通道」分离。

| 答案分支 | 架构差异 |
| --- | --- |
| 接管即完全退出 | 状态机简单，审计清晰；但一线失去辅助 |
| 接管后只读 + 仅建议 | 双通道权限分离（建议/执行），每次建议仍需权限再校验；审计更复杂但体验好 |
| 接管后仍可半自动执行 | 风险最高，需要动作级二次确认与责任人绑定 |

**本项目答案（假设）**
**接管后机器人只读、仅提供建议，不得执行任何动作**。出现 GPS 弱网、客户改地址、回执延迟、依据缺失或关键系统不可用时，**停止自动建议并标明原因、接手人、人工确认时间** [f44]。日志保留版本、建议内容、人工修正与签核人，能重建当次处理，不记录口令与非必要个人信息 [f45]。修正**只追加不覆盖**。
**待确认**：接管人能否转交、接管原因是否强制必填（建议强制）。

## Q8 授权按什么粒度：角色、运单，还是客户主体？

**为什么先问**
司机定位与收件人电话是受限数据。授权粒度决定能否做行级权限、字段脱敏和越权检测——做不到，自动回复就不能对外。

| 答案分支 | 架构差异 |
| --- | --- |
| 角色 RBAC | 简单；无法满足「客户只能查自己授权的运单」 |
| 运单级 ABAC | 策略引擎（PEP/PDP）+ 运单-客户关系 + 字段级脱敏 + 访问审计 |
| 客户主体级 | 需要主体-运单归属关系与授权生命周期管理；撤销传播复杂 |

**本项目答案（假设）**
**运单级 ABAC + 字段级白名单**：客户只能查自己授权的运单 [f40]；定位、电话默认脱敏，按字段白名单放行。先做**只读授权矩阵草案**，合规确认后才进入并行试点，未确认前只出内部草稿。
**待确认**：授权由谁授予、按运单还是客户主体、变更撤销如何生效、越权如何发现与处置。

## Q9 部署与模型放在哪：公有云、私有化，还是混合？

**为什么先问**
20 万预算下，部署形态直接决定模型选型、数据出域合规与运维成本，也决定「能不能用强模型」。

| 答案分支 | 架构差异 |
| --- | --- |
| 公有云 SaaS + 云模型 API | 上线快、成本低；必须有脱敏网关与出域审批，敏感字段不出域 |
| 全私有化 + 本地模型 | 合规可控；硬件/运维/效果调优成本高，20 万预算紧张 |
| 混合（控制面本地 + 生成走合规网关） | 需要模型路由与分级策略，复杂度中等，最贴近现实 |

**本项目答案（假设）**
**混合优先**：规则、映射、审计留在本地；生成侧走合规网关，敏感字段脱敏后再出域，必要时降级到本地小模型。预算 20 万需覆盖**接口改造、培训、复核、维护**四项，既有系统采购不计入节省额 [f03]。
**待确认**：企业网络与数据出域政策、TMS 部署位置、是否允许调用外部模型。

## Q10 验收怎么算：15 分钟和 10% 误报，分母是谁定的？

**为什么先问**
指标定义不清，试点一定各说各话；只考核单一指标还会产生反向激励（少报异常来达标）。

| 答案分支 | 架构差异 |
| --- | --- |
| 只看业务结果 | 无法归因，争议无法复盘 |
| 事件日志 + 指标服务 + 回放 | 需要事件溯源、指标口径配置、历史回放沙箱、标注与评测集 |
| 再加 A/B 与灰度 | 需要分流与对照实验能力，成本更高，首期不建议 |

**本项目答案（假设）**
以**事件日志为一等公民**：每条结果带数据时间、来源、版本，超一个刷新周期标「待刷新」，历史快照不能伪装成当前状态 [f34]。验收看三组指标：
1. **异常首次响应 ≤15 分钟**（基线 90 分钟）[f00]
2. **预警误报率 ≤10%**，且预警须关联轨迹、计划、异常记录 [f42]
3. **回复可追溯率 / 人工修正率**（草稿被采纳比例）
外加**人工接管率**与**越权访问次数**作为反向激励的制衡。到货准时率（88%）与回执及时率（63%）**分开统计**，单据原因单独归类 [f51]；各部门完成时间分别记录，分母、周期、排除规则由业务负责人固定，**不能用消息发送量代替完成量** [f53]。
**状态**：指标已采集；口径待业务负责人固定。

## 十问收敛出的架构决策

1. **单干线、单班次、草稿制起步**，人工流程并行保留，不直接关闭 [f05]。
2. **事件模型先收窄**：固定核心枚举 + 可配置原因码；模型不定级。
3. **独立映射服务**：运单↔子单多对多 + 四要素校验 + 人工修复队列 + 只读快照版本。
4. **只读集成**，不回写、不下发路线；接口失败降级到原人工流程。
5. **草稿工作台**是唯一出口，客服主管是签核点；无发送网关。
6. **规则分层**：红线硬编码，路由可配置且版本化；接管强制留痕。
7. **运单级 ABAC + 字段级脱敏 + 访问审计**；未审批前只出内部草稿。
8. **append-only 审计**，90 天留存，不含口令与非必要个人信息 [f43][f45]。
9. **可观测先行**：事件日志、指标口径、回放沙箱在开发前定义。
