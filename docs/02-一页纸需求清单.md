# 一页纸需求清单 · 运输异常与签收协作智能体系统

> 版本 v0.1 · 2026-10-30 · 全部为待验证假设，试点前需业务负责人签字

## 1. 目标与基线

| 项 | 内容 |
| --- | --- |
| 业务目标 | 异常首次响应从 **90 分钟 → 15 分钟**；不增加司机与一线操作负担 |
| 基线 | 日均 **1800 票**，异常件 **9%**；到货准时率 **88%**，回执及时率 **63%** |
| 试点范围 | **一条干线**，先历史回放、再并行试点，**不关闭现有人工流程** |
| 预算 | 20 万元（含接口改造、培训、复核、维护；既有系统采购不计入节省） |

## 2. 范围

**做**
- 异常事件结构化（类型 + 原因码 + 处理人 + 截止时间 + 退回原因）
- 运单↔子单映射、事件归一、快照版本与人工修复队列
- 查单/催单的**证据化回复草稿**（带原记录、数据时间、来源、版本）
- 异常预警（关联轨迹 + 计划 + 异常记录）与超时升级
- 客服审核台、调度待办、人工接管与审计留痕
- 到货 / 回执**分开统计**，单据原因单独归类

**不做**
- 不自动判责、不自动结算或扣罚承运商
- 不直接对客户发送消息（仅草稿，客服主管签核后人工发出）
- 不回写 TMS、不下发路线控制
- 不承诺赔付金额（须主管批准）
- 不把「已送达」当「客户签收」

## 3. 角色与权限

| 角色 | 可见 | 可做 | 不可做 |
| --- | --- | --- | --- |
| 现场调度 | 本干线运单、异常、轨迹 | 报异常、分派、确认接手 | 改原记录、判责 |
| 客服 | 授权运单 + 证据包 | 生成/修改草稿、回访 | 承诺赔付、越权查单 |
| 客服主管 | 本组全部 | 核对草稿、确认对外、认定争议 | 绕过接管规则 |
| 运输负责人 | 全干线 | 定范围、定指标口径、超时协调 | 越过合规否决 |
| 安全与合规主管 | 全量审计 | 风险否决、字段白名单、接管规则 | — |
| 承运商经理 | 本承运商交接结果 | 受理反馈、核实归类 | 判责、扣罚 |
| 客户 | 仅自己授权运单 | 查询进度（脱敏字段） | 查看定位/电话原值 |

## 4. 核心流程（5 步）

1. **采集**：司机在现有终端「先选类型、再补关键信息」，保留待补状态与最后同步时间，不新增登录。
2. **归一**：校验主编号/事件时间/来源/版本；缺字段进人工修复队列，不猜值；多子单按来源优先级归并。
3. **路由**：红线类型 → 直接人工接管；其余按类型 + 超时路由到具名处理人（含截止时间与退回原因）。
4. **辅助**：生成查单回复草稿与预警，附原记录链接、数据更新时间、置信度；超一个刷新周期标「待刷新」。
5. **交接与闭环**：接手人显式确认才结束本岗待办；发消息 ≠ 责任转移；超时上报运输负责人。

## 5. 系统边界与集成

| 系统 | 方式 | 能力边界 |
| --- | --- | --- |
| TMS | **只读**：查单、异常记录 | 无路线控制；不写回 |
| GPS / 轨迹 | 只读，**5 分钟**刷新 | 不能承诺更细时效；弱网与停驶需区分 |
| 签收回执 | 读取，可能延迟 **24 小时** | 必须标注数据更新时间与置信度 |
| IM 群消息 | 首期不接入为数据源 | 人工留痕补充（待确认） |
| 模型 | 合规网关 / 本地降级 | 敏感字段脱敏后出域 |

## 6. 数据与口径（硬规则）

- 主键：TMS 运单号为主，承运商子单为从属，多对多映射带版本。
- 每条结论必须可追溯到原记录 + 数据时间 + 来源 + 版本。
- 缺关键字段 → 人工修复队列；**禁止用推测值补齐**。
- 接口失败 → 回退人工流程，保留只读快照与时间戳；恢复后按业务编号去重补齐。
- 到货与回执分别计数；单据原因单独归类；不用「消息发送量」代替「实际完成量」。

## 7. 红线与人工接管

- **必须人工接管**：赔付、危险品处置、紧急事故（无例外）。
- **停止自动建议**：GPS 弱网、客户改地址、回执延迟、依据缺失、关键系统不可用；须标明原因、接手人、人工确认时间。
- **接管后**：机器人只读、仅建议，不得执行；不得覆盖原记录。
- **审计**：记录版本、建议内容、人工修正、签核人；append-only；留存 90 天；不记口令与非必要个人信息。

## 8. 验收指标

| 指标 | 目标 | 口径要求 |
| --- | --- | --- |
| 异常首次响应 | ≤ 15 分钟 | 分母/周期/排除规则由运输负责人固定 |
| 预警误报率 | ≤ 10% | 预警须关联轨迹+计划+异常记录 |
| 回复可追溯率 | 100% 草稿带原记录 | 客服主管逐条核对 |
| 人工修正率 | 试点期持续下降 | 作为质量主指标 |
| 制衡指标 | 人工接管率、越权访问次数 | 防止「少报异常」达标 |

## 9. 里程碑

| 阶段 | 产出 | 通过条件 |
| --- | --- | --- |
| M0 需求确认 | 十问定稿 + 8 项缺口闭环 | 业务、合规、TMS 三方签字 |
| M1 历史回放 | 一条干线近两周草稿 | 可追溯率 100%，人工修正可归类 |
| M2 并行试点 | 单干线单班次辅助 | 人工流程不关闭，无越权事件 |
| M3 复盘固化 | 周复盘 + 规则更新 | 复测 15 分钟 / 10% 达标 |

## 10. 关键假设与风险

- **假设**：单干线可代表全网；15 分钟指「异常被具名责任人受理」而非「客户收到回复」。
- **风险**：映射与时间口径不清 → 误报放大；授权与撤销未闭合 → 不能对外；接管语义不清 → 审计断链。
- **停止条件**：误报率连续两周 >10%，或出现越权访问、未授权对外发送，立即暂停并回到人工流程。
