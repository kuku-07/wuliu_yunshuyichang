# 运输异常与签收协作智能体系统

> 当前进度：需求与接口设计（v0.1）+ 阶段 1 可运行原型 + 阶段 2 一线问答（网页 + SSE）+ 阶段 3 管理后台。

## 一句话定位

用「异常事件归一 + 证据可追溯的查单回复草稿 + 具名人工接管」，把异常首次响应从 **90 分钟压到 15 分钟**，并把到货与回执分开看；**不做自动判责、不做自动扣罚、不直接对客户发消息**。

```powershell
.\run_admin.ps1                                  # 登录后左侧「一线问答」
$env:PYTHONPATH="D:\Lib\site-packages;$PWD"; python scripts\smoke_chat.py
```

要点：

- 事件协议与错误码按项目内约定的聊天接口契约实现；
  鉴权沿用后台已有的 Cookie 会话，不单独引入 Bearer Token。
- 检索的是**已发布**的规则切片（`kb_chunks.is_active=1`），后台改规则后对话立刻生效。
- 提示词取后台「提示词模板」的**已发布版本**，不是硬编码常量。
- 红线在调用模型之前拦截：命中时 0 次模型调用、0 条 `delta`，只发 `takeover`。
- 带运单号提问时先做**运单级授权预检**：运单号格式（默认 `YD` + 11 位数字）、
  运单是否在主数据、运单线路与会话线路是否一致、授权是否有效、授权线路是否匹配，
  任一条不满足都在流开始前拒绝（格式非法 400，其余 403 `SHIPMENT_FORBIDDEN`），
  不检索、不调用模型；授权在「运单授权」页维护（仅系统管理员）。
- 授权通过后，运单的**客户与在途状态**会作为上下文进入提示词，并在对话页顶部显示；
  这些字段在「运单登记」页维护（登记 / 改客户与状态 / 删除，仅系统管理员）。
- 演示数据（规则文档 / 会话 / 账号 / 运单 / 授权）默认保留，全部带 `is_demo` 标记；
  可在「数据管理」页**逐条删除**，删完还能**按组恢复**，重启不会自动回填。
- 「提示词模板」里当前生效的话术以**浅色占位文字**显示，输入正式话术后即被替换，
  不会把提示文字当成正文保存；没有编辑权限的角色（如合规审计）会看到明确的只读说明。
- 对话首屏是引导态：标题 + 6 个可点的常见问题，点一下填入输入框，发送后自动收起。
- 对话页左侧是会话栏：可新建、切换、删除会话（只能看到并操作自己的会话）。
- 会话栏底部可切换**作业线路**：切换后检索范围与运单校验都按该线路走。
  干线在「干线管理」页维护：名称随便起（不必带地区），所属地区从固定列表里选
  （华北 / 华南 / 华中 / 华东 / 西南 / 西北 / 东北 / 西藏 / 新疆 / 港澳）；
  新建后规则上传、运单登记、对话下拉同步出现。
  演示数据里有华东、华北、华南三份规则（延误阈值、回执时限、照片张数各不相同），
  切线路问同一个问题，引用会变成对应片区的文档。
- 线路内检索**不会跨线路兜底**：某条线路没有生效规则时返回「未覆盖 + 需人工复核」，
  而不是拿别的片区的规则来回答。
- 每次问答都落 `messages` / `citations` / `audit_logs`，「对话审计」页看到的是真实会话。
- 没有 `LLM_API_KEY` 时走离线抽取（`OfflineExtractiveLLM`），只验证检索与引用完整性；
  配置 `LLM_PROVIDER=openai_compatible` + `LLM_API_KEY` 后才由真模型生成。

```powershell
.\run_admin.ps1     # 登录后左侧「业务」：异常与修复 / 查单工作台 / 指标
```

要点：

- **金路径**：样本 → 运单/子单/轨迹入库 → 异常四要素校验（缺字段进修复队列，不猜值）
  → 证据包（运单 + 子单 + 轨迹 + 异常 + 数据时间）→ 闸门 → 草稿（带引用）
  → 人工审核（通过/退回/转人工）→ 审计可重建。
- 赔付、危险品等红线在生成草稿前拦截，直接转人工，不产出草稿。
- 指标口径：到货与回执分开算，越权拦截单列。
- 消息与审计日志保留 90 天，到期整批清理。
- **异常受理与升级**：受理后开始计时，首次响应 ≤30 分钟、处置 ≤2 小时，
  逾期自动升级并留原因；支持指派处理人。
- **异常预警**：预计超时 / 轨迹停滞 / 回执超期 / 多异常聚集四条确定性规则，
  可确认或标误报，指标页给出误报率。
- **账号与线路权限**：`/admin/users` 新建账号、改角色与线路范围、重置密码、解锁；
  非系统管理员的干线下拉按 `lane_scopes` 过滤，切到范围外会被拒绝。
- **接入层**：TMS 支持样本 / HTTP 两种模式（`TMS_BASE_URL` 切换，带超时与重试）；
  GPS 轨迹与 IM 留痕走 `POST /admin/api/ingest/tracks`、`/ingest/im`（`X-Ingest-Token`）。
- **子单映射**：`shipment_links` 保留多来源，按「优先级 → 版本」归并出生效口径，查单页可追溯到候选来源。
- **审核与留痕**：退回必须选修正原因（证据不足/口径错误/引用不符/越界/其他），
  审核通过后可登记「已由人工外发」（渠道 + 时间 + 登记人），指标页给出修正率与外发率。
- **审计导出异步化**：POST 创建任务 → 后台生成 CSV → 在「导出记录」页下载。
- **待办与通知**：后台每分钟巡检一次超时与预警；升级/预警/指派会生成站内通知，
  「我的待办」汇总通知、指派给我的异常、待我审核的草稿。
- **聊天重试**：错误气泡带「重试」，直接复用上一次提问。
- 口径：异常首响**目标 15 分钟**、规则硬性时限 **30 分钟**（超时升级），指标页两者都给。
- **快照版本**：每次接入留带版本全量数据；**催单**与查单分场景生成。
- **自动路由与交接**：按类型路由到具名处理人；转交显式留痕，发消息不算责任转移。
- **停止自动建议**：GPS 弱网、客户改地址、回执延迟时停止生成，转人工。
- **误报率熔断**：最近 14 天误报率 >10% 自动暂停草稿生成。
- **留存合规**：清理需「申请 → 合规审批 → 执行」，申请人不能自批。
- **角色门户**：现场调度可处置异常；承运商/客户只读 `/portal` 授权运单。
- **两个入口一个大脑**：
  - 员工端：`/login` → `/agent`（只有问答，无后台导航）
  - 管理端：`/admin/login` → `/admin/*`（规则、审计、账号、数据）
  - 两边共用同一套问答服务、会话与审计；权限始终按账号角色判定，入口只决定落地页。

## 项目原则（先于技术选型）

1. **只读优先**：首期只消费 TMS 查单与异常记录接口，不写回、不下发路线。
2. **证据先于结论**：每条辅助结果必须带原记录、数据时间、来源与版本；无证据不给结论。
3. **人机边界清晰**：系统只产出草稿与待办，赔付/危险品/紧急事故必须人工接管。
4. **不可逆动作前设确定性校验**：所有对外动作、判责、结算前必须过规则闸门。
5. **失败可降级**：接口失败回退原人工流程，保留只读快照与时间戳，不发「猜出来的」结论。
6. **只追加不覆盖**：修正留痕，能重建「谁在何时依据什么改了什么」。
7. **口径先定、指标后算**：分母、统计周期、排除规则由业务负责人固定，不用消息量代替完成量。

## 里程碑（不含开发排期）

- **M0 需求确认**：十问答案定稿，八个待确认项闭环。
- **M1 历史回放**：一条干线近两周数据，离线生成草稿，客服主管逐条核对。
- **M2 并行试点**：单干线、单班次，人工流程不关闭，只做草稿辅助。
- **M3 周复盘与固化**：复测「首次响应 15 分钟、误报率 ≤10%」后才更新规则。
