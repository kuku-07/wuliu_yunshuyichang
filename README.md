# 运输异常与签收协作智能体系统

> 当前进度：需求与接口设计（v0.1）+ 阶段 1 可运行原型 + 阶段 3 管理后台。阶段 2（`/chat` SSE）只有设计，尚未实现。

## 一句话定位

用「异常事件归一 + 证据可追溯的查单回复草稿 + 具名人工接管」，把异常首次响应从 **90 分钟压到 15 分钟**，并把到货与回执分开看；**不做自动判责、不做自动扣罚、不直接对客户发消息**。

## 项目原则（先于技术选型）

1. **只读优先**：首期只消费 TMS 查单与异常记录接口，不写回、不下发路线。
2. **证据先于结论**：每条辅助结果必须带原记录、数据时间、来源与版本；无证据不给结论。
3. **人机边界清晰**：系统只产出草稿与待办，赔付/危险品/紧急事故必须人工接管。
4. **不可逆动作前设确定性校验**：所有对外动作、判责、结算前必须过规则闸门。
5. **失败可降级**：接口失败回退原人工流程，保留只读快照与时间戳，不发「猜出来的」结论。
6. **只追加不覆盖**：修正留痕，能重建「谁在何时依据什么改了什么」。
7. **口径先定、指标后算**：分母、统计周期、排除规则由业务负责人固定，不用消息量代替完成量。

## 逻辑架构（分层，非代码）

```
┌──────────────────────────────────────────────────────────┐
│ L1 接入层   TMS 适配器(只读) · GPS/轨迹(5min) · IM 留痕(可选) │
├──────────────────────────────────────────────────────────┤
│ L2 归一与主数据   事件归一 · 运单↔子单映射 · 快照版本 · 修复队列 │
├──────────────────────────────────────────────────────────┤
│ L3 智能体编排   意图识别(查单/催单/异常) · 只读工具调用 ·      │
│                证据包生成 · 回复草稿 · 预警评估               │
├──────────────────────────────────────────────────────────┤
│ L4 规则与决策   红线硬拦截 · 分类/超时路由 · 接管判定 · 版本化  │
├──────────────────────────────────────────────────────────┤
│ L5 人机协同     客服审核台 · 调度待办 · 接管与转交 · 反馈闭环   │
├──────────────────────────────────────────────────────────┤
│ L6 治理与观测   审计日志(append-only) · 指标服务 · 回放 · 权限/脱敏 │
└──────────────────────────────────────────────────────────┘
```

## 里程碑（不含开发排期）

- **M0 需求确认**：十问答案定稿，八个待确认项闭环。
- **M1 历史回放**：一条干线近两周数据，离线生成草稿，客服主管逐条核对。
- **M2 并行试点**：单干线、单班次，人工流程不关闭，只做草稿辅助。
- **M3 周复盘与固化**：复测「首次响应 15 分钟、误报率 ≤10%」后才更新规则。
