# 管理后台（阶段 3）

服务端渲染的 SaaS 风格后台，覆盖五批能力：

1. 登录鉴权（JWT Cookie + 角色权限 + CSRF）
2. 一线问答（`/admin/chat`：SSE 流式、红线接管、引用面板，见阶段 2）
3. 运单登记（`/admin/shipments`：运单主数据增删改）
4. 运单级授权（`/admin/grants`：谁可以查哪一票；授权自动绑定运单归属线路，仅系统管理员）
5. 规则知识库（上传 → 解析 → 切片 → 审核 → 发布 → 索引切换）
6. 提示词模板（锁定安全段 + 草稿 → 试跑 → 发布 → 回滚）
7. 对话审计（筛选 → 详情 → 标记 → 导出 → 发布记录）
8. 数据管理（演示数据逐条删除 / 按组恢复，仅系统管理员）
9. 干线管理（`/admin/lanes`：新建干线（名称 + 地区）、停用 / 删除，仅系统管理员）
10. 异常与修复（`/admin/exceptions`：TMS 样本导入、异常归一、受理/关闭/指派、超时升级、预警）
11. 查单工作台（`/admin/workbench`：证据包 → 草稿 → 审核）
12. 指标（`/admin/metrics`：归一率、首响/处置达标率、草稿通过率、接管/越权、预警误报率）
13. 账号管理（`/admin/users`：新建账号、角色与线路范围、重置密码、解锁，仅系统管理员）

其中「一线问答」的规则检索走的是知识库里**已生效**的切片，提示词走模板的**已发布**版本；
问答产生的消息、引用与审计事件都会落库，所以「对话审计」页展示的就是真实会话。

设计依据：本文档上文的角色权限矩阵与页面清单

## 启动

```powershell
.\run_admin.ps1
```

打开 <http://127.0.0.1:8088/admin/login>。

演示账号（密码均为 `Admin@123456789`，可用环境变量 `ADMIN_SEED_PASSWORD` 覆盖）：

| 账号 | 姓名 | 角色 |
| --- | --- | --- |
| rule_admin | 张敏 | 规则管理员 |
| supervisor | 李强 | 客服主管（批准） |
| supervisor2 | 赵敏 | 客服主管（发布） |
| auditor | 王芳 | 合规审计 |
| sys_admin | 陈磊 | 系统管理员 |

默认职责分离：规则由 rule_admin 提交 → supervisor 批准 → **supervisor2** 发布；同一账号无法完成全流程。

**系统管理员是例外**：可以上传/编辑/提交/批准/发布规则与提示词，也能自审自批，
但这类操作会在审计里标记「系统管理员自审自批」。要恢复严格三方分离，
删掉 `deps.py` 中 `sys_admin` 的 `kb:approve` / `kb:publish` / `prompt:publish` 即可。

## 说明

- 数据库与上传文件位于 `admin_app/data/`，首次启动自动建表并写入演示数据。
- 上传仅支持 `.md` / `.pdf`（≤20MB）；无文字层的扫描 PDF 会被拒绝。
- 提示词锁定段在数据库字段层不可修改，接口会拒绝并返回 `PROMPT_LOCKED_SECTION`。
- 可编辑话术段的默认内容是**浅色占位提示**，输入正式话术后即被替换；直接提交空内容会被拒绝。
- 审计标记为追加式，撤销保留原记录。
- 阶段 2 的一线问答已接入：`/admin/chat`，SSE 流式，红线在调用模型前拦截。
